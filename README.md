# MesensV3-testers

Сайт для набора бета-тестеров Mesens V3.

## Как это работает

1. Пользователь заполняет форму на странице (`index.html`, публикуется через GitHub Pages).
2. При отправке форма **не хранит и не отправляет никакие пароли** и не использует
   зашитый в код токен — вместо этого она открывает предзаполненный
   GitHub Issue в этом репозитории (пользователю нужен GitHub-аккаунт, чтобы
   подтвердить создание issue).
3. GitHub Action (`.github/workflows/process-application.yml`) автоматически
   срабатывает на новый issue с меткой `beta-application`, прогоняет ответы
   через `scripts/classify.py` и:
   - если Telegram указан и оба обязательных ответа длиннее 50 символов и не
     похожи на "клавиатурный мусор" — сохраняет заявку в `beters/<ник>.md`;
   - иначе — сохраняет в `badrequest/<ник>.md`;
   - комментирует и закрывает issue.

## Почему так, а не токен в JS

Раньше в похожей форме GitHub-токен был зашит прямо в HTML/JS — это значит,
что **любой посетитель страницы мог открыть исходный код и увидеть токен**,
а с ним — писать что угодно в привязанный репозиторий (или использовать токен
для других целей, если у него были более широкие права). Схема с Issues +
Action не хранит никаких секретов на клиенте: токен, которым Action пишет
в репозиторий, генерируется GitHub автоматически на время выполнения и никому
не виден.

## Публикация (GitHub Pages)

Страница публикуется из ветки `main`, корень репозитория.
